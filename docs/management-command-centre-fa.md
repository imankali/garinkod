# مرکز مدیریت گرین کود

## مسیر

```text
/management
```

این مسیر فقط برای کاربران Django با `is_staff=True` باز می‌شود. مالک یا سوپریوزر می‌تواند نقش‌ها را مدیریت کند.

## نقش‌های آماده

برای ساخت یا به‌روزرسانی نقش‌ها:

```bash
cd garinkood
python manage.py bootstrap_management_roles
```

| نقش | دسترسی اصلی |
|---|---|
| عملیات | سفارش‌ها، سبد، محصول و کوپن |
| مالی | سفارش، پرداخت، ledger، کیف پول، کوپن و affiliate conversion |
| بازار و غرفه | غرفه، آگهی، پست/استوری و شکایت غرفه |
| پشتیبانی | درخواست خدمت، خرید محصول کشاورز، feedback، شکایت و کامنت |
| محتوا | کامنت، پست/استوری، آگهی و اطلاعات محصول |
| انبار | محصول، موجودی و سفارش |

## اصل کمترین دسترسی

- مدیر مالی نباید بدون نیاز، اجازه حذف محصول یا moderation محتوا داشته باشد.
- مدیر محتوا نباید payout یا تأیید پرداخت انجام دهد.
- فقط owner/superuser می‌تواند نقش‌ها و فعال/غیرفعال‌بودن کارمندان را تغییر دهد.
- هیچ token، رمز عبور یا credential پرداختی نباید در پنل یا Git ذخیره شود.

## بخش‌های فعلی داشبورد

- KPI فروش پرداخت‌شده
- سفارش‌های در انتظار بررسی
- شکایت‌های باز
- پست/استوری و آگهی در انتظار بررسی
- محصولات با موجودی کم
- تعداد غرفه‌های تأییدشده و affiliateهای فعال
- آخرین سفارش‌ها و action تأیید پرداخت
- صدور پاداش خرید بعدی هنگام تأیید پرداخت
- مدیریت نقش کارمندان برای owner
- audit log اقدامات مدیریتی

## Audit Log

اعمال زیر در `AdminAuditLog` ثبت می‌شوند:

- تغییر نقش کارمند
- تأیید پرداخت سفارش از مرکز مدیریت
- moderation کامنت، پست و آگهی از API مدیریت

تغییرهای مستقیم Django Admin در حال حاضر از امکانات استاندارد Admin Log استفاده می‌کنند؛ برای audit یکپارچهٔ production می‌توان signal یا middleware مخصوص اضافه کرد.
